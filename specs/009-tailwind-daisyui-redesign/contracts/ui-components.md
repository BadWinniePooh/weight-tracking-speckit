# UI Component Contracts: Tailwind CSS + DaisyUI Redesign

**Feature**: 009-tailwind-daisyui-redesign
**Date**: 2026-03-16

These contracts define the required DOM structure, stable identifiers, and DaisyUI component classes
for each shared UI component. Implementation MUST satisfy these contracts. Tests MUST query only via
the stable identifiers listed here.

---

## Component: Navbar (Authenticated Pages)

**Applies to**: `index.html`, `profile.html`, `admin.html`

### Required DOM structure (schematic)

```html
<nav id="main-navbar" class="navbar ...">
  <!-- Brand -->
  <a id="nav-brand" href="/index.html">Weight Tracker</a>

  <!-- Desktop links (hidden on mobile) -->
  <ul id="nav-links-desktop">
    <li><a id="nav-dashboard" href="/index.html">Dashboard</a></li>
    <li><a id="nav-profile" href="/profile.html">Profile</a></li>
    <li><a id="nav-admin" href="/admin.html" hidden>Admin Dashboard</a></li>
  </ul>

  <!-- Logout button (always visible) -->
  <button id="logout-button" type="button">Log out</button>

  <!-- Hamburger (mobile only) -->
  <button id="nav-hamburger" type="button" aria-label="Open navigation menu">☰</button>
</nav>

<!-- Mobile menu drawer (hidden by default) -->
<div id="nav-mobile-menu" hidden>
  <ul id="nav-links-mobile">
    <li><a id="nav-mobile-dashboard" href="/index.html">Dashboard</a></li>
    <li><a id="nav-mobile-profile" href="/profile.html">Profile</a></li>
    <li><a id="nav-mobile-admin" href="/admin.html" hidden>Admin Dashboard</a></li>
    <li><button id="nav-mobile-logout" type="button">Log out</button></li>
  </ul>
</div>
```

### Stable identifiers

| Element | Identifier | Notes |
|---------|-----------|-------|
| Nav container | `id="main-navbar"` | |
| Brand link | `id="nav-brand"` | |
| Desktop links container | `id="nav-links-desktop"` | |
| Dashboard link | `id="nav-dashboard"` | active class on current page |
| Profile link | `id="nav-profile"` | active class on current page |
| Admin link | `id="nav-admin"` | `hidden` for non-admin users |
| Logout button | `id="logout-button"` | EXISTING — must not change |
| Hamburger button | `id="nav-hamburger"` | |
| Mobile menu | `id="nav-mobile-menu"` | toggled by hamburger |

### Behavioral contracts

- `nav-admin` (desktop) and `nav-mobile-admin` must be `hidden` for users with role `user`
- `nav-admin` must be visible for users with role `admin`
- The link matching the current page must carry `aria-current="page"`
- `logout-button` calls `POST /api/auth/logout` then redirects to `/login.html` (existing behavior)

## Component: Public Page Card (Unauthenticated Pages)

**Applies to**: `login.html`, `setup.html`, `reset-request.html`, `reset-complete.html`

### Required DOM structure (schematic)

```html
<div id="public-page-root" class="min-h-screen flex items-center justify-center bg-base-200">
  <div id="auth-card" class="card w-full max-w-md bg-base-100 shadow-xl">
    <div class="card-body">
      <h1 id="page-title" class="card-title">...</h1>
      <!-- Form content -->
      <!-- Footer link -->
    </div>
  </div>
</div>
```

### Stable identifiers

| Element | Identifier | Notes |
|---------|-----------|-------|
| Page root | `id="public-page-root"` | |
| Auth card | `id="auth-card"` | |
| Page title | `id="page-title"` | h1 or h2 |

All existing form field `id` attributes (e.g., `username`, `password`, `email-input`, `submit-btn`)
MUST be preserved unchanged.

## Component: Status Badge

**Applies to**: Admin user table (dynamically generated in `admin.ts`)

### Stable identifier contract

Dynamically generated `<span>` elements for user status MUST carry:

```html
<span data-status="active"    class="badge badge-success">Active</span>
<span data-status="inactive"  class="badge badge-error">Deactivated</span>
<span data-status="pending"   class="badge badge-warning">Pending</span>
```

The `data-status` attribute is the stable identifier for tests.

## Component: Entry Table Row (index.html — dynamically generated)

**Applies to**: Weight entry rows generated by `ui.ts`

### Stable identifier contract

Each `<tr>` generated by `ui.ts` MUST contain cells with:

```html
<td data-cell="weight">...</td>
<td data-cell="date">...</td>
<td data-cell="time">...</td>
<td data-cell="actions">
  <button data-action="delete" ...>Delete</button>
</td>
```

The empty-state element MUST have:

```html
<p id="entry-empty-state" ...>No entries yet.</p>
```

### Test migration contract

Tests in `ui.test.ts` MUST be updated from:
- `row.querySelector(".entry-weight")` → `row.querySelector('[data-cell="weight"]')`
- `row.querySelector(".entry-date")` → `row.querySelector('[data-cell="date"]')`
- `row.querySelector(".entry-time")` → `row.querySelector('[data-cell="time"]')`
- `row.querySelector(".entry-actions")` → `row.querySelector('[data-cell="actions"]')`
- `document.querySelector(".empty-state")` → `document.getElementById("entry-empty-state")`

## Component: Confirmation Modal (Destructive Actions)

**Applies to**: Admin user deactivation, any future destructive action

### Required DOM structure (schematic)

```html
<dialog id="confirm-modal" class="modal">
  <div class="modal-box">
    <h3 id="confirm-modal-title" class="font-bold text-lg">...</h3>

    <div class="modal-action">
      <button id="confirm-modal-yes" class="btn btn-error">Confirm</button>
      <button id="confirm-modal-cancel" class="btn">Cancel</button>
    </div>
  </div>
</dialog>
```

### Stable identifiers

| Element | Identifier |
|---------|-----------|
| Dialog | `id="confirm-modal"` |
| Title | `id="confirm-modal-title"` |
| Message | `id="confirm-modal-message"` |
| Confirm button | `id="confirm-modal-yes"` |
| Cancel button | `id="confirm-modal-cancel"` |

## Component: Loading Button State

**Applies to**: All submit/action buttons during API calls

### Contract

When an API call is in-flight, the triggering button MUST:
1. Have `disabled` attribute set
2. Have `data-loading="true"` attribute set (for test visibility)
3. Show DaisyUI `loading` class (spinner)

When the call completes (success or error):
1. Remove `disabled` attribute
2. Remove `data-loading` attribute
3. Remove `loading` class

---

## Component: Inline Form Error

**Applies to**: All forms with validation

### Contract

Error text for a form field MUST appear in a `<span>` or `<div>` immediately after the input,
with:
- `role="alert"` (already present in most existing forms)
- `id` attribute matching `aria-describedby` on the input

DaisyUI error styling: `text-error text-sm` or use `<label class="label"><span class="label-text-alt text-error">...</span></label>` pattern.

Existing `id` attributes on error elements (e.g., `error-msg`, `username-feedback`, `cu-feedback`)
MUST be preserved unchanged.
