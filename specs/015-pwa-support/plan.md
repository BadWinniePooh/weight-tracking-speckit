# Implementation Plan: PWA Support

**Branch**: `015-pwa-support` | **Date**: 2026-03-18 | **Spec**: [spec.md](./spec.md)

## Summary

Add Progressive Web App support to the weight-tracking frontend so users can install it as a native-like app on Android, desktop, and iOS. Implementation uses `vite-plugin-pwa` (Workbox-based) to auto-generate a service worker and inject the web app manifest into all 8 HTML entry points at build time. No offline caching is implemented — the service worker is a minimal pass-through that satisfies Chrome's installability requirements. Acceptance is validated by Vitest build-output tests that assert manifest correctness, icon file existence, and service worker generation.

## Technical Context

**Language/Version**: TypeScript 5.x (browser target ES2020); Node.js 20+ (build tooling)
**Primary Dependencies**: Vite 5.x (build), `vite-plugin-pwa` (new), Workbox (via plugin), Tailwind CSS v4 + DaisyUI v5 (existing)
**Storage**: N/A — no new data storage; static build artifacts only
**Testing**: Vitest 2.x + Node.js `fs` (file system assertions on `dist/` output)
**Target Platform**: Browser (Chrome Android, Chrome desktop, Safari iOS); served via nginx:alpine in Docker
**Project Type**: Frontend web application (multi-page, 8 HTML entry points)
**Performance Goals**: No regression to existing build size; SW file is minimal (no precache manifest)
**Constraints**: No offline support; HTTPS required (already satisfied by Traefik in production); install prompt via browser heuristics only
**Scale/Scope**: Frontend-only change; no backend or Docker Compose modifications
