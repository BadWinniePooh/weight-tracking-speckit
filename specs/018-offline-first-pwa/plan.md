# Implementation Plan: Offline-First PWA, Foldable History, Week-Long Sessions

**Branch**: `018-offline-first-pwa` | **Date**: 2026-07-30 | **Spec**: [spec.md](./spec.md)

## Summary

Make the main page fully offline-capable: a namespaced localStorage offline store with
a per-user pending-operation queue, a main-thread FIFO sync engine triggered by app
load and the `online` event, client-side chart computation via the existing
`computeChartData`, a precached app shell, and an offline-tolerant auth guard backed by
a persisted expiry marker. Backend gets three surgical changes: id-conflict protection
on entry creation, a 60-second refresh-rotation grace window, and auth-constant
deduplication. The History card becomes a DaisyUI collapse, default folded.

## Key Decisions

### D1 — localStorage offline store, `wt_offline::` namespace

A decade of daily entries is ~365 KB — far below quota. jsdom tests localStorage
natively (IndexedDB would need `fake-indexeddb`). The legacy keys
(`weight_tracker_entries` …) are off-limits: `migration-tool.ts` scans them on every
main-page load and would surface the "Migrate my data" button for pending offline
entries. Keys:

| Key | Content |
|-----|---------|
| `wt_offline::auth` | `{ userId, role, refreshExpiresAt }` |
| `wt_offline::<userId>::entries` | last known server entries |
| `wt_offline::<userId>::pending` | FIFO `PendingOp[]` |
| `wt_offline::<userId>::settings` | cached ChartSettings |
| `wt_offline::config` | cached `{ apiUrl }` |

Offline delete-all: drop pending creates, enqueue one delete per cached id, clear the
cache — only ids this client has seen (FR-004). Online delete-all keeps the bulk
endpoint.

### D2 — Main-thread sync engine, no Background Sync API

Background Sync is unsupported on iOS Safari and would force injectManifest. Sync only
needs to run while the app is open. Triggers: post-auth load, `online` event,
after local writes. Single-flight promise (same pattern as `_refreshPromise` in
api-client.ts). FIFO replay; TypeError → stop and keep queue; delete-404 / create-4xx →
drop op and continue. After drain: refetch entries + settings, rewrite caches,
`onAfterSync` re-render callback.

### D3 — Chart always computed client-side

`refreshChart()` switches from server `getChartData()` to
`computeChartData(entries, settings, unit)` (`chart-calculations.ts:184`) — the module
is production-dead today, 91% mutation score, and mirrors `ChartCalculationService.cs`.
One code path online/offline. `/api/chart` and `getChartData()` remain untouched.

### D4 — generateSW with app-shell precache

`globPatterns: ["**/*.{js,css,html,png,svg,ico,webmanifest,woff2}"]` — all 8 pages are
a few KB each; login.html must render offline for the expired-marker redirect, and
selective precaching would leave the plugin's default `navigateFallback` pointing at a
non-precached index.html (the current broken state). `navigateFallbackDenylist:
[/^\/api\//]`. `runtimeCaching` NetworkFirst for `/config.json` (generated by
entrypoint.sh at container start — unavailable at build time). No `/api/*` caching.
`loadConfig()` additionally falls back to `wt_offline::config` — jsdom-testable,
SW-independent.

### D5 — Auth marker and guard changes

Marker written on every successful login/refresh with `refreshExpiresAt = now + 7 d`
(mirrors the server's sliding cookie); cleared on logout and any 401 refresh.
`checkAuthStatus()` keeps its signature; `AuthState` gains optional `offline?: boolean`.
The current code's unused `error: "Network error"` branch becomes the offline path:
network-throw + valid marker → `{ isAuthenticated: true, offline: true, role }`.
Network-throw + expired marker → the existing unauthenticated state (redirects to the
precached login page). The refresh `catch` at auth-guard.ts:35 is split: HTTP 401
clears the marker; fetch-throw goes to the offline path. `enforceRedirect` is
unchanged. The marker gates only the local UI shell.

### D6 — Backend: three changes

1. **`WeightEntryRepository.AddAsync` id-conflict fix (security)**. Today
   `FindAsync(id)` ignores UserId and the endpoint echoes the found entity with 201 —
   replaying a foreign id reads another user's entry. New contract:
   `Task<(WeightEntry Entry, AddOutcome Outcome)>` with
   `enum AddOutcome { Inserted, AlreadyExists, IdConflict }`. Endpoint maps
   201 / 200 (own replay, existing entry) / 409 (foreign, no data echo). The sync
   client drops ops on 409.
2. **60 s rotation grace** in `RefreshTokenRepository.GetActiveByHashAsync`:
   `RevokedAt == null || RevokedAt > UtcNow.AddSeconds(-60)`. No migration.
3. **`AuthConstants`** in Domain: `RefreshTokenDays = 7` (currently duplicated in
   JwtTokenService.cs and AuthEndpoints.cs), `AccessTokenMinutes = 15`,
   `AccessTokenSeconds = 900` (currently hardcoded twice in responses).

### D7 — History fold: DaisyUI checkbox collapse

Inside the existing card-body: `.collapse.collapse-arrow` >
unchecked `input#history-toggle[type=checkbox]` + `.collapse-title` (holds
`h2#history-heading`) + `.collapse-content` (holds the existing
`div.overflow-x-auto > #entry-list`). No JS, no persistence — unchecked on every load
is the default-folded requirement. `#entry-list` stays the direct parent of the
rendered table, so `renderEntryList`, the delegated click handler, ui.test.ts
selectors, and the 009 contract are untouched.

## Risks

1. First-visit-offline unsupported (by design, documented).
2. Cross-tab: single-flight is per-tab; convergence relies on id idempotency +
   delete-404 tolerance.
3. Client chart is now user-facing — client/server chart test suites must stay paired.
4. 60 s grace window weakens rotation replay protection (accepted).
5. main.ts bootstrap is the riskiest diff for the existing 388 tests — module
   boundaries (checkAuthStatus / enforceRedirect / loadConfig signatures) stay stable,
   `offline?` is additive.
